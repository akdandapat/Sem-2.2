> **Given the center point coordinate (10, -5) and a radius of 8 units, generate all the points (in the 4th octant) by using both the Bresenham and Midpoint circle drawing algorithms. ### 🧠 Mathematical Formulations and Steps

Before applying the final translation to the screen center point (Xc, Yc) = (10, -5), we first calculate the baseline pixel positions centered at the origin (0, 0) for the standard baseline octant (where x ranges from 0 up to y, meaning x <= y).

To transform these baseline coordinates into the true **4th octant** (where x is negative, y is positive, and |x| >= y, going from the line x = -y down to the negative x-axis), the standard octant symmetry mapping is:
- Origin Point mapped to 4th Octant: (-y, x)

Finally, we apply translation to shift the points to the given center:
- X_screen = -y + Xc = -y + 10
- Y_screen = x + Yc = x - 5

---

#### 1️⃣ Midpoint Circle Drawing Algorithm

- **Initial Values:** x = 0, y = 8
- **Initial Decision Parameter:** p0 = 1 - R = 1 - 8 = -7
- **Parameter Update Rules:**
  - If pk < 0: p(k+1) = pk + 2x + 3. Next point is (x + 1, y).
  - If pk >= 0: p(k+1) = pk + 2x - 2y + 5. Next point is (x + 1, y - 1).

#### 🛠️ Efficiency and Complexity Analysis

1. **Computational Complexity:** Both algorithms require O(N) time complexity, where N is the number of pixels plotted along the circle arc segment. They completely replace expensive floating-point or trigonometric calculations with fast integer additions, subtractions, and bit shifts.
2. **Computational Counts:** The Midpoint method increments the decision parameter using linear variables (2x + 3 or 2x - 2y + 5), while Bresenham's uses structural steps (4x + 6 or 4(x - y) + 10). They make identical pixel-plotting choices because Bresenham's parameter is mathematically related to the Midpoint parameter by d = 2p - 1. Therefore, operational speed is identical on modern systems.

#### 📌 Part (b)
> **Consider a non-interlaced raster monitor with a resolution of n by m (m scan lines and n pixels per scan line), a refresh rate of r frames per second, a horizontal retrace time of t_horizontal and a vertical retrace time of t_vertical. What is the fraction of the total refresh time per frame spent in retrace of the electron beam.** `[Marks: 3]`

##### 💡 Solution:

1. **Total Time for One Complete Frame (T_frame):**
   Given a refresh rate of r frames per second, the total allocation for one frame is:
   - T_frame = 1 / r seconds

2. **Total Retrace Time Inside One Frame (T_retrace):**
   An electron beam performs a horizontal retrace after every single scan line, and a vertical retrace once at the end of the full screen:
   - Total Horizontal Retrace Time = m * t_horizontal
   - Total Vertical Retrace Time = t_vertical
   - T_retrace = (m * t_horizontal) + t_vertical

3. **Fraction of Total Refresh Time Spent in Retrace:**
   - Fraction = T_retrace / T_frame
   - Fraction = ((m * t_horizontal) + t_vertical) / (1 / r)
   - **Fraction = r * ((m * t_horizontal) + t_vertical)**

### 📥 QUESTION 2

#### 📌 Part (a)
> **A cubic splined curve has start and end point at (20, 0) and (7, 2) respectively. The tangent vectors at start and end points meet at (18, 9). Determine the Hermite cubic spline curve and hence find out its mid-point.** `[Marks: 7]`

##### 💡 Solution:
Given boundary parameters:
- Start position: P0 = (20, 0)
- End position: P1 = (7, 2)
- Tangent intersection vertex: V = (18, 9)

1. **Deriving Tangent Vectors:**
   The tangent vector at the start points from P0 towards the intersection point V, and the ending tangent points from V towards P1:
   - P'(0) = V - P0 = (18 - 20, 9 - 0) = (-2, 9)
   - P'(1) = P1 - V = (7 - 18, 2 - 9) = (-11, -7)

2. **Hermite Curve Parametric Blending Equation:**
   P(t) = (2*t^3 - 3*t^2 + 1)*P0 + (-2*t^3 + 3*t^2)*P1 + (t^3 - 2*t^2 + t)*P'(0) + (t^3 - t^2)*P'(1)

3. **Calculating the Mid-point (t = 0.5):**
   Substitute t = 0.5 into the blending function weight coefficients:
   - Weight 1 = 2*(0.125) - 3*(0.25) + 1 = 0.5
   - Weight 2 = -2*(0.125) + 3*(0.25) = 0.5
   - Weight 3 = 0.125 - 2*(0.25) + 0.5 = 0.125
   - Weight 4 = 0.125 - 0.25 = -0.125

   Now compute coordinate values at t = 0.5:
   - X(0.5) = 0.5*(20) + 0.5*(7) + 0.125*(-2) - 0.125*(-11)
   - X(0.5) = 10 + 3.5 - 0.25 + 1.375 = **14.625**

   - Y(0.5) = 0.5*(0) + 0.5*(2) + 0.125*(9) - 0.125*(-7)
   - Y(0.5) = 0 + 1 + 1.125 + 0.875 = **3.0**

   - **Curve Mid-point:** **(14.625, 3.0)**

### 📥 QUESTION 3

> **The lower left-hand and upper right-hand corners of a rectangular clipping window are at (50, 10) and (80, 40), respectively. Using Sutherland-Cohen algorithm, check and find the visibility portion of the quadrilateral PQRS for P(35,10) Q(65,40), R(65,20), and S(95,10) in the clipping window.** `[Marks: 9]`

##### 💡 Solution:

##### 1️⃣ Region Boundary Codes
Outcodes are assigned using 4 bits: **[Top, Bottom, Right, Left]**.
Window Limits: Xmin = 50, Xmax = 80, Ymin = 10, Ymax = 40

- **Point P(35, 10):** X < Xmin -> Outcode is **0001** (Left)
- **Point Q(65, 40):** Inside all boundaries -> Outcode is **0000** (Inside)
- **Point R(65, 20):** Inside all boundaries -> Outcode is **0000** (Inside)
- **Point S(95, 10):** X > Xmax -> Outcode is **0010** (Right)

---

##### 2️⃣ Segment-by-Segment Clipping Execution

##### 🔴 Segment PQ (P(35, 10) to Q(65, 40))
- Codes: P = 0001, Q = 0000. Logical AND = 0000 (Partially visible candidate).
- Clip P against Left boundary (X = 50):
  - Slope m = (40 - 10) / (65 - 35) = 30 / 30 = 1.0
  - Y_intersect = 10 + 1.0 * (50 - 35) = 25
  - New point P' = **(50, 25)** [Code 0000]
- **Visible Line Component:** **P'(50, 25) to Q(65, 40)**.

##### 🔴 Segment QR (Q(65, 40) to R(65, 20))
- Codes: Q = 0000, R = 0000.
- Both endpoints are 0000 -> Trivial Accept.
- **Visible Line Component:** **Q(65, 40) to R(65, 20)**.

##### 🔴 Segment RS (R(65, 20) to S(95, 10))
- Codes: R = 0000, S = 0010. Logical AND = 0000.
- Clip S against Right boundary (X = 80):
  - Slope m = (10 - 20) / (95 - 65) = -10 / 30 = -0.333
  - Y_intersect = 20 + (-0.333) * (80 - 65) = 20 - 5 = 15
  - New point S' = **(80, 15)** [Code 0000]
- **Visible Line Component:** **R(65, 20) to S'(80, 15)**.

##### 🔴 Segment SP (S(95, 10) to P(35, 10))
- Codes: S = 0010, P = 0001. Logical AND = 0000.
- Clip S against Right boundary (X = 80):
  - Y is constant at 10.
  - New point S'' = **(80, 10)** [Code 0000]
- Clip P against Left boundary (X = 50):
  - Y is constant at 10.
  - New point P'' = **(50, 10)** [Code 0000]
- **Visible Line Component:** **S''(80, 10) to P''(50, 10)**.

---

### 🎯 Final Summary of Visible Quadrilateral
The clipped visible portion forms a custom polygon with the following sequential vertices:
1. **P'(50, 25)**
2. **Q(65, 40)**
3. **R(65, 20)**
4. **S'(80, 15)**
5. **S''(80, 10)**
6. **P''(50, 10)**

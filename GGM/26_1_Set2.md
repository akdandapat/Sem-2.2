### 🧠 Mathematical Formulations and Steps

Before applying the final translation to the screen center point (Xc, Yc) = (15, 10), we first calculate the baseline pixel positions centered at the origin (0, 0) for the standard baseline octant (where x ranges from 0 up to y, meaning x <= y).

To transform these baseline coordinates into the true **3rd octant** (where x is negative, y is positive, and |x| <= y), the standard octant symmetry mapping is:
- Origin Point mapped to 3rd Octant: (-x, y)

Finally, we apply translation to shift the points to the given center:
- X_screen = -x + Xc = -x + 15
- Y_screen = y + Yc = y + 10

#### 🛠️ Efficiency and Complexity Analysis

1. **Computational Complexity:** Both algorithms require O(N) time complexity, where N is the number of pixels plotted along the circle arc segment. They completely replace expensive floating-point or trigonometric calculations with fast integer additions, subtractions, and bit shifts.
2. **Computational Counts:** The Midpoint method increments the decision parameter using linear variables (2x + 3 or 2x - 2y + 5), while Bresenham's uses structural steps (4x + 6 or 4(x - y) + 10). They make identical pixel-plotting choices because Bresenham's parameter is mathematically related to the Midpoint parameter by d = 2p - 1. Therefore, operational speed is identical on modern systems.

#### 📌 Part (b)
> **How long would it take to load a 640x480 frame buffer with 12 bits per pixel, if 10^5 bits can be transferred per second? How long would it take to load a 24-bit per pixel frame buffer with a resolution of 1280x1024 using this same transfer rate?** `[Marks: 3]`

##### 💡 Solution:

**Scenario 1: 640x480 Monitor**
1. Total pixels = 640 * 480 = 307,200 pixels
2. Total memory bits = 307,200 pixels * 12 bits/pixel = 3,686,400 bits
3. Transfer speed = 10^5 bits per second = 100,000 bits/sec
4. Time taken = 3,686,400 / 100,000 = **36.864 seconds**

**Scenario 2: 1280x1024 Monitor**
1. Total pixels = 1280 * 1024 = 1,310,720 pixels
2. Total memory bits = 1,310,720 pixels * 24 bits/pixel = 31,457,280 bits
3. Transfer speed = 10^5 bits per second = 100,000 bits/sec
4. Time taken = 31,457,280 / 100,000 = **314.573 seconds**

### 📥 QUESTION 2

#### 📌 Part (a)
> **Given a cubic Bezier curve defined by the control points P1(-8,0,0), P2(-4,5,0), P3(4,-5,0) and P4(8,0,0). Determine the geometric coefficient matrix that reproduces this curve in the cubic Hermite form.** `[Marks: 7]`

##### 💡 Solution:
A cubic Hermite curve is defined by its two endpoints and the tangent vectors at those two endpoints. The geometric coefficient matrix GH is structured as:
GH = [ P(0), P(1), P'(0), P'(1) ] transposed

For a cubic Bezier curve with control points P1, P2, P3, P4:
1. The start point P(0) corresponds exactly to the first control point:
   - P(0) = P1 = (-8, 0, 0)
2. The end point P(1) corresponds exactly to the last control point:
   - P(1) = P4 = (8, 0, 0)
3. The starting tangent vector P'(0) is given by:
   - P'(0) = 3 * (P2 - P1) = 3 * (-4 - (-8), 5 - 0, 0 - 0) = 3 * (4, 5, 0) = (12, 15, 0)
4. The ending tangent vector P'(1) is given by:
   - P'(1) = 3 * (P4 - P3) = 3 * (8 - 4, 0 - (-5), 0 - 0) = 3 * (4, 5, 0) = (12, 15, 0)

##### 📋 Final Hermite Geometric Matrix (GH):
```
[ -8,  0,  0 ]  <- Start Position P(0)
[  8,  0,  0 ]  <- End Position P(1)
[ 12, 15,  0 ]  <- Start Tangent Vector P'(0)
[ 12, 15,  0 ]  <- End Tangent Vector P'(1)
```

### 📥 QUESTION 3

> **The lower left-hand and upper right-hand corners of a rectangular clipping window are at (-3, 1) and (2, 6), respectively. Using Sutherland-Cohen algorithm, check and find the visibility portion of the quadrilateral EFGH for E(-4,2), F(-1,7), G(-1,5) and H(-2,3) in the clipping window.** `[Marks: 9]`

##### 💡 Solution:

##### 1️⃣ Region Boundary Codes
Outcodes are assigned using 4 bits: **[Top, Bottom, Right, Left]**.
Window Limits: Xmin = -3, Xmax = 2, Ymin = 1, Ymax = 6

- **Point E(-4, 2):** X < Xmin -> Outcode is **0001** (Left)
- **Point F(-1, 7):** Y > Ymax -> Outcode is **1000** (Top)
- **Point G(-1, 5):** Inside all boundaries -> Outcode is **0000** (Inside)
- **Point H(-2, 3):** Inside all boundaries -> Outcode is **0000** (Inside)

---

##### 2️⃣ Segment-by-Segment Clipping Execution

##### 🔴 Segment EF (E(-4, 2) to F(-1, 7))
- Codes: E = 0001, F = 1000. Logical AND = 0000 (Partially visible candidate).
- Clip E against Left boundary (X = -3):
  - Slope m = (7 - 2) / (-1 - (-4)) = 5 / 3 = 1.667
  - Y_intersect = 2 + 1.667 * (-3 - (-4)) = 3.667
  - New point E' = (-3, 3.667) [Code 0000]
- Clip F against Top boundary (Y = 6):
  - X_intersect = -1 + (6 - 7) / 1.667 = -1.6
  - New point F' = (-1.6, 6) [Code 0000]
- **Visible Line Component:** **E'(-3, 3.667) to F'(-1.6, 6)**.

##### 🔴 Segment FG (F(-1, 7) to G(-1, 5))
- Codes: F = 1000, G = 0000. Logical AND = 0000.
- Clip F against Top boundary (Y = 6):
  - X is constant at -1.
  - New point F'' = (-1, 6) [Code 0000]
- **Visible Line Component:** **F''(-1, 6) to G(-1, 5)**.

##### 🔴 Segment GH (G(-1, 5) to H(-2, 3))
- Codes: G = 0000, H = 0000. 
- Both endpoints are 0000 -> Trivial Accept.
- **Visible Line Component:** **G(-1, 5) to H(-2, 3)**.

##### 🔴 Segment HE (H(-2, 3) to E(-4, 2))
- Codes: H = 0000, E = 0001. Logical AND = 0000.
- Clip E against Left boundary (X = -3):
  - Slope m = (2 - 3) / (-4 - (-2)) = -1 / -2 = 0.5
  - Y_intersect = 3 + 0.5 * (-3 - (-2)) = 2.5
  - New point E'' = (-3, 2.5) [Code 0000]
- **Visible Line Component:** **H(-2, 3) to E''(-3, 2.5)**.

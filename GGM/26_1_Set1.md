### 🧠 Mathematical Formulations & Steps

Before applying the transformation to the center $(X_c, Y_c) = (20, 16)$, we always derive the points centered at the origin $(0, 0)$ for the standard **$2^{\text{nd}}$ octant** (where $x$ ranges from $0$ to $y$, i.e., $x \le y$). 

Once a point $(x, y)$ is computed, its final screen coordinate is found by translating it to the given center:
$$\mathbf{X_{\text{screen}} = x + X_c = x + 20}$$
$$\mathbf{Y_{\text{screen}} = y + Y_c = y + 16}$$

#### 🛠️ Efficiency & Complexity Comparison

1. **Computational Complexity:** Both algorithms exhibit an **$\mathcal{O}(N)$** time complexity where $N$ represents the total number of pixels plotted in the octant. They completely eliminate costly floating-point arithmetic and trigonometric evaluations, utilizing exclusively integer additions, subtractions, and left bit-shifts (multiplication by 2 or 4).
2. **Number of Calculations:** * **Midpoint Algorithm:** Evaluates the decision parameter using linear step increments ($2x_k + 3$ or $2x_k - 2y_k + 5$).
   * **Bresenham's Algorithm:** Uses structural parameter updates ($4x_k + 6$ or $4(x_k - y_k) + 10$). 
   * Both perform the identical pixel choices because the decision parameter in Bresenham's is fundamentally a scaled version of the Midpoint parameter ($d_k = 2 \cdot p_k - 1$). Thus, their procedural execution efficiency is completely identical on modern hardware architectures.

##### 💡 Solution:
1. **Determine Monitor Resolution:**
   $$	ext{Width in pixels } (W) = 12 	ext{ inches} 	imes 120 	ext{ pixels/inch} = 1440 	ext{ pixels}$$
   $$	ext{Height in pixels } (H) = 14 	ext{ inches} 	imes 120 	ext{ pixels/inch} = 1680 	ext{ pixels}$$
2. **Determine Memory Per Pixel:**
   $$	ext{Storage per pixel} = 4 	ext{ bits} = 0.5 	ext{ bytes}$$
3. **Calculate Frame Buffer Address For Coordinates $(x, y)$:**
   Assuming a standard row-major order tracking from top-left $(0,0)$ up to $(W-1, H-1)$:
   $$	ext{Total pixels prior to line } y = y 	imes W$$
   $$	ext{Total pixels in line } y 	ext{ prior to column } x = x$$
   $$	ext{Total accumulated pixels} = y 	imes W + x = 1440 \cdot y + x$$
4. **Convert to Byte Address:**
   $$	ext{Address} = 	ext{Starting Address} + (	ext{Total Pixels} 	imes 	ext{Storage per pixel in bytes})$$
   $$\mathbf{	ext{Address} = 0 + (1440 \cdot y + x) 	imes 0.5 = 720 \cdot y + 0.5 \cdot x 	ext{ bytes}}$$

#### 📌 Part (b)
> **Suppose the knot vector of a B-spline is $\{0,0,0,1,2,3,3,3\}$. Find the possible values of number of control points and degree of the polynomial.** `[Marks: 3]`

##### 💡 Solution:
Let $n+1$ be the total number of control points, $p$ be the degree of the polynomial ($k = p+1$ is the order), and $m+1$ be the total number of knots in the vector.
The fundamental relationship for a B-spline curve is:
$$\mathbf{m = n + p + 1}$$

From the given knot vector $\{0,0,0,1,2,3,3,3\}$, we count the number of elements:
$$	ext{Total knots} = m + 1 = 8 \implies m = 7$$

Substituting $m = 7$ into the formula gives:
$$7 = n + p + 1 \implies \mathbf{n + p = 6}$$

Since the multiplicity of the endpoint knots is $3$ (there are three $0$s at the start and three $3$s at the end), the maximum possible degree $p$ matching this standard clamped condition is $p = 2$. Let us explore valid academic combinations:
1. **If Degree $p = 2$ (Quadratic Spline, Order $k=3$):**
   $$n + 2 = 6 \implies n = 4 \implies 	ext{Number of Control Points } (n+1) = \mathbf{5}$$
2. **If Degree $p = 1$ (Linear Spline, Order $k=2$):**
   $$n + 1 = 6 \implies n = 5 \implies 	ext{Number of Control Points } (n+1) = \mathbf{6}$$

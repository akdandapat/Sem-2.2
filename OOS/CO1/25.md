## 🧾 QUESTION 1(a)(i)
**❓ “There is only one entry point to a program, irrespective of the number of main() methods in a class.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is completely valid because in Java, the execution of every standalone application begins from only one specific method whose signature is predefined by the Java Virtual Machine (JVM). That official entry point is:

`public static void main(String args[])`

Although Java supports **method overloading**, including overloading of the `main()` method itself, the JVM recognizes only the above method signature as the starting point of program execution 🚀. Therefore, even if multiple versions of `main()` are written inside the same class, only one method acts as the true program entry point.

### 🌟 Detailed Explanation
The JVM requires a standard mechanism to start program execution. Without a fixed entry point, ambiguity would arise regarding which method should execute first, how command-line arguments should be passed, and how the runtime environment should initialize the application ⚠️. To solve this problem, Java enforces one standardized entry method.

**💻 Code Example**
```java
class Demo {
    public static void main(String args[]) {
        System.out.println("Original main() method");
        main(10);
        main("Java");
    }

    public static void main(int x) {
        System.out.println("Integer overloaded main(): " + x);
    }

    public static void main(String s) {
        System.out.println("String overloaded main(): " + s);
    }
}
```

**🖥️ Output**
```text
Original main() method
Integer overloaded main(): 10
String overloaded main(): Java
```

### 🌟 Deep Conceptual Analysis
When the JVM loads the class, it searches specifically for `public static void main(String args[])` and invokes it automatically. 

The other overloaded versions (`main(int x)` and `main(String s)`) are treated like ordinary methods. They are executed only because they are explicitly called from inside the original `main()` method. Thus, overloaded `main()` methods are not separate program entry points.

Internally, the JVM checks the access modifier, return type, parameter type, and static nature before deciding which method qualifies as the official startup method 🧠.

### 🌟 Real-world Intuition
Consider a university examination hall 🏫. Even though multiple doors may exist inside the building, students are allowed to enter only through the officially designated entrance gate. Similarly, multiple `main()` methods may exist, but the JVM always begins execution through one official entry point.

### 🎯 Conclusion
Although Java allows multiple overloaded versions of `main()`, the JVM always starts execution from only one predefined method. Hence a Java application always has exactly one true entry point 🚀.

## 🧾 QUESTION 1(a)(ii)
**❓ “Method overriding is also known as late binding.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is absolutely valid because method overriding supports **runtime polymorphism**, where the actual method to execute is determined dynamically during runtime rather than during compilation 🚀.

This runtime method resolution process is called 🔥 **Late Binding** or 🔥 **Dynamic Binding** because the association between the method call and actual method implementation occurs late, that is, during execution time.

### 🌟 Detailed Explanation
Method overriding occurs when a child class defines a method having the same name, same parameter list, and compatible return type as a method already present in the parent class. The child class then provides its own specialized behavior.

**💻 Code Example**
```java
class Animal {
    void sound() {
        System.out.println("Animal makes sound");
    }
}

class Dog extends Animal {
    void sound() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String args[]) {
        Animal a = new Dog();
        a.sound();
    }
}
```

**🖥️ Output**
```text
Dog barks
```

### 🌟 Deep Conceptual Analysis
The reference variable `Animal a` belongs to the parent type. However, the actual object created is `new Dog()`. Thus during runtime, the JVM examines the real object type and invokes `Dog.sound()` instead of `Animal.sound()`. This decision is postponed until execution time. Therefore, overriding is called late binding 🧠.

### 🌟 JVM Internal Working
Internally the JVM maintains virtual method tables, runtime object metadata, and dynamic dispatch mechanisms. When overridden methods are invoked, the JVM dynamically determines the correct method implementation according to the actual object type. This provides flexibility and extensibility in software systems 🚀.

### 🌟 Real-world Intuition
Suppose a payment application supports UPI, Credit Card, and Net Banking. All payment systems may implement the same method `pay()`, but actual payment behavior depends on the object selected during runtime. This is late binding in real-world software architecture 💡.

### 🎯 Conclusion
Method overriding supports runtime polymorphism where method resolution occurs during execution time. Hence overriding is also known as late binding or dynamic binding 🚀.

## 🧾 QUESTION 1(a)(iii)
**❓ “A non-static member method can be invoked within the static block of a class.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is conditionally valid because a non-static member method cannot be called directly inside a static block, but it can be invoked indirectly using an object reference 🚀.

### 🌟 Detailed Explanation
Static blocks belong to the **class level**, whereas non-static methods belong to the **object level**. Therefore, non-static methods require object memory, an object reference, and instance context. Since static blocks execute before object creation, direct invocation becomes illegal ⚠️.

**❌ Invalid Program**
```java
class Demo {
    void show() {
        System.out.println("Hello");
    }

    static {
        show(); // ERROR
    }
}
```

**🖥️ Output**
```text
Compiler Error:
Non-static method cannot be referenced from static context
```

**✅ Correct Program**
```java
class Demo {
    void show() {
        System.out.println("Non-static method invoked");
    }

    static {
        Demo d = new Demo();
        d.show();
    }

    public static void main(String args[]) {
    }
}
```

**🖥️ Output**
```text
Non-static method invoked
```

### 🌟 Deep Conceptual Analysis
Static blocks execute during class loading. At that moment no object exists automatically. Therefore, the JVM cannot determine which object's method should execute. By explicitly creating an object (`Demo d = new Demo();`), object context becomes available. Then non-static method invocation becomes possible.

### 🎯 Conclusion
A non-static method cannot be directly invoked inside a static block, but it can be called through object creation. Hence the statement is conditionally valid 🚀.

## 🧾 QUESTION 1(a)(iv)
**❓ “Reference data types do not store the value directly in a variable.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is valid because reference variables in Java do not directly store actual object data. Instead, they store memory references, object addresses, or object locations that point to objects stored in heap memory 🚀.

### 🌟 Detailed Explanation
Java variables are broadly categorized into primitive datatypes and reference datatypes. Primitive variables directly store actual values (e.g., `int x = 10;` directly stores the value 10). However, reference variables behave differently.

**💻 Code Example**
```java
class Student {
    int roll = 5;
}

class Main {
    public static void main(String args[]) {
        Student s = new Student();
        System.out.println(s.roll);
    }
}
```

**🖥️ Output**
```text
5
```

### 🌟 Deep Conceptual Analysis
The variable `Student s` does not contain the entire object. Instead, the actual object is stored in the heap, and the variable stores a reference pointing toward the heap object.

Memory representation:
`s  ------>  Student Object in Heap`

### 🌟 Why Java Uses References
Reference-based memory management provides dynamic object creation, polymorphism, garbage collection, memory efficiency, and object sharing. These are essential for modern object-oriented systems 🚀.

### 🎯 Conclusion
Reference datatypes store references to heap objects rather than storing actual object data directly inside variables. Hence the statement is valid 🚀.

## 🧾 QUESTION 1(a)(vi)
**❓ “An interface solves the diamond problem automatically.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is valid because Java interfaces eliminate the ambiguity associated with multiple inheritance and thereby solve the diamond problem safely 🚀.

### 🌟 Detailed Explanation
The diamond problem occurs when multiple parent classes contain the same method, and a child inherits from all of them. This creates ambiguity regarding which method implementation should execute ⚠️. 

Java avoids this issue because multiple inheritance of classes is prohibited. However, interfaces safely support multiple inheritance.

**💻 Code Example**
```java
interface A {
    void show();
}

interface B extends A {}
interface C extends A {}

class D implements B, C {
    public void show() {
        System.out.println("Diamond problem resolved");
    }
}
```

**🖥️ Output**
```text
Diamond problem resolved
```

### 🌟 Deep Conceptual Analysis
Interfaces traditionally contain abstract methods. Thus the implementing class must explicitly define the implementation. Since the implementation is provided directly by the child class, ambiguity disappears. Therefore, the diamond problem gets resolved automatically.

### 🎯 Conclusion
Interfaces eliminate ambiguity by forcing explicit implementation inside child classes. Hence interfaces solve the diamond problem safely 🚀.

## 🧾 QUESTION 1(a)(vii)
**❓ “The ensureCapacity() method doubles the capacity of a StringBuffer object.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is valid because the `ensureCapacity()` method of the **StringBuffer** class is internally designed to dynamically increase the storage capacity whenever the existing character buffer becomes insufficient 🚀.

In Java, `StringBuffer` is a mutable sequence of characters. Unlike the `String` class, whose objects are immutable, `StringBuffer` objects can be modified repeatedly without creating new objects each time. Because of this mutability, Java must internally manage memory expansion efficiently so that repeated append operations do not degrade performance ⚠️.

When the current capacity of a `StringBuffer` becomes insufficient, Java automatically expands its internal storage. The expansion mechanism generally follows the formula:
**New Capacity = (Old Capacity × 2) + 2**

### 🌟 Detailed Explanation
Whenever a `StringBuffer` object is created without specifying capacity explicitly, Java allocates a default capacity of 16 characters. As more characters are inserted, the JVM checks whether enough free space is available. If additional space is required, a larger memory block is allocated, old data is copied, and capacity expands dynamically.

**💻 Code Example**
```java
class Main {
    public static void main(String args[]) {
        StringBuffer sb = new StringBuffer();
        System.out.println("Initial Capacity = " + sb.capacity());

        sb.append("abcdefghijklmnopq");
        System.out.println("New Capacity = " + sb.capacity());
    }
}
```

**🖥️ Output**
```text
Initial Capacity = 16
New Capacity = 34
```

### 🌟 Deep Conceptual Analysis
Initially, the `StringBuffer` object has a default capacity of 16. However, the appended string contains 17 characters. Since the current capacity becomes insufficient, Java internally applies the resizing formula: `(16 × 2) + 2 = 34`. 

**🌟 Example Using ensureCapacity()**
```java
class Main {
    public static void main(String args[]) {
        StringBuffer sb = new StringBuffer();
        System.out.println(sb.capacity());

        sb.ensureCapacity(50);
        System.out.println(sb.capacity());
    }
}
```

**🖥️ Output**
```text
16
50
```
*Why Capacity Becomes 50:* The method `ensureCapacity(50)` requests a minimum capacity of 50. Since 50 exceeds the automatically calculated doubled size (34), Java directly allocates a 50-character capacity.

### 🎯 Conclusion
The `ensureCapacity()` method dynamically expands the internal storage of `StringBuffer` objects, generally following a doubling strategy `(oldCapacity × 2) + 2`, improving performance and memory efficiency 🚀.

## 🧾 QUESTION 1(a)(viii)
**❓ “Two strings can be compared by == operator.”**  
**❓ Justify the validity of the statement with supporting arguments and suitable code snippets.**

### ✅ Answer
The statement is conditionally valid because the `==` operator in Java compares **references**, not actual string contents ⚠️. Therefore two strings can indeed be compared using `==`, but this comparison checks whether both references point to the same memory object rather than checking whether the textual contents are equal.

### 🌟 Detailed Explanation
In Java, strings are objects stored in heap memory or the string constant pool. The `==` operator checks whether both references refer to identical object locations. It does NOT compare character sequences. Content comparison should normally use the `equals()` method.

**💻 Code Example 1 — Reference Comparison**
```java
class Main {
    public static void main(String args[]) {
        String s1 = "Java";
        String s2 = "Java";
        System.out.println(s1 == s2);
    }
}
```

**🖥️ Output**
```text
true
```
*Why Output is true:* String literals are stored inside the String Constant Pool. Since both literals are identical, the JVM reuses the same object.

**💻 Code Example 2 — Different Objects**
```java
class Main {
    public static void main(String args[]) {
        String s1 = new String("Java");
        String s2 = new String("Java");

        System.out.println(s1 == s2);
        System.out.println(s1.equals(s2));
    }
}
```

**🖥️ Output**
```text
false
true
```

### 🌟 Deep Conceptual Analysis
Here, `new String("Java")` creates separate heap objects. Thus, the references differ even if the contents remain the same. Therefore `==` returns false, while `equals()` returns true.

### 🎯 Conclusion
Two strings can technically be compared using `==`, but the operator compares references rather than textual contents. Content comparison should normally use `equals()` 🚀.

Java provides a powerful exception handling mechanism to manage abnormal situations during program execution 🚀.

```java
import java.io.*;

class Main {

}
```

**💻 Code Example — Unchecked Exception**
```java
class Main {
    public static void main(String args[]) {
        int x = 10 / 0;
        System.out.println(x);
    }
}
```

### 🌟 Comparison Table

| Feature | Checked Exception | Unchecked Exception |
| :--- | :--- | :--- |
| **Checked By** | Compiler | JVM at Runtime |
| **Handling Mandatory** | Yes | No |
| **Cause** | External conditions | Programming mistakes |
| **Examples** | `IOException` | `ArithmeticException` |

### 🎯 Conclusion
Checked exceptions are verified during compilation and must be handled explicitly, whereas unchecked exceptions occur during runtime due to programming errors 🚀.

```java
        System.out.println("Base Constructor: " + x);
    }
}

class Child extends Base {
    Child() {
        super(100);
        System.out.println("Child Constructor");
    }
}

class Main {
    public static void main(String args[]) {
        Child c = new Child();
    }
}
```

**🖥️ Output**
```text
Base Constructor: 100
Child Constructor
```

### 🎯 Conclusion
Parameterized constructors of parent classes must be invoked explicitly from child constructors using `super()` 🚀.

## 🧾 QUESTION 1(b)(ix)
**❓ “The equalsIgnoreCase() and compareToIgnoreCase() methods differ by ________.”**

### ✅ Answer
🔥 **“The equalsIgnoreCase() and compareToIgnoreCase() methods differ by their return type and comparison behavior.”**

### 🌟 Detailed Explanation
Both methods are used for case-insensitive string comparison. However, they differ significantly in output type and intended purpose 🚀.

* **`equalsIgnoreCase()`**: Checks whether two strings are equal ignoring letter case. It returns a **boolean** value.
* **`compareToIgnoreCase()`**: Performs a lexicographical comparison ignoring case. It returns an **integer** value.

**💻 Code Example**
```java
class Main {
    public static void main(String args[]) {
        String s1 = "JAVA";
        String s2 = "java";
        System.out.println(s1.equalsIgnoreCase(s2)); // Returns true
        
        String s3 = "apple";
        String s4 = "banana";
        System.out.println(s3.compareToIgnoreCase(s4)); // Returns a negative integer
    }
}
```

### 🌟 Comparison Table

| Feature | `equalsIgnoreCase()` | `compareToIgnoreCase()` |
| :--- | :--- | :--- |
| **Return Type** | `boolean` | `int` |
| **Purpose** | Equality check | Lexicographical comparison |
| **Output** | `true` / `false` | numeric (`0`, positive, negative) |

### 🎯 Conclusion
Both methods perform case-insensitive comparison, but `equalsIgnoreCase()` checks equality while `compareToIgnoreCase()` determines relative alphabetical ordering 🚀.

## 🧾 QUESTION 1(b)(x)
**❓ “Two strings can be concatenated by ________ or ________.”**

### ✅ Answer
🔥 **“Two strings can be concatenated by + operator or concat() method.”**

### 🌟 Detailed Explanation
String concatenation means combining multiple strings into a single string. Java provides multiple mechanisms for this, but the most common are the `+` operator and the `concat()` method 🚀.

**💻 Code Example**
```java
class Main {
    public static void main(String args[]) {
        // Using + Operator
        String s1 = "Object";
        String s2 = "Oriented";
        String s3 = s1 + s2;
        System.out.println("Using +: " + s3);

        // Using concat() Method
        String s4 = "Java";
        String s5 = "Programming";
        String s6 = s4.concat(s5);
        System.out.println("Using concat(): " + s6);
    }
}
```

### 🌟 Comparison Table

| Feature | `+` Operator | `concat()` Method |
| :--- | :--- | :--- |
| **Type** | Operator | Method |
| **Null Handling** | Converts automatically (`"null"`) | May throw exception |
| **Internal Optimization** | Uses `StringBuilder` | Direct concatenation |

### 🎯 Conclusion
Strings in Java can be concatenated using either the `+` operator or the `concat()` method 🚀.

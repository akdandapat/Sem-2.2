## 🧾 QUESTION 3(a)
**❓ Consider the following code snippet. Point out the problems and state how to solve them.**
```java
Scanner sc = new Scanner(System.in);
int a = sc.nextInt();
System.out.println("a = " + a);
String s = sc.nextLine();
System.out.println("s = " + s);
char ch = sc.nextChar();
System.out.println("ch = " + ch);
```

### ✅ Answer
This program contains multiple important problems related to:
* Input buffering
* Scanner limitations
* Character input handling

These are extremely common mistakes made by beginners ⚠️.

### 🌟 Problem 1 — `nextLine()` Skipping Input
After:
```java
int a = sc.nextInt();
```
the `ENTER` key remains inside the input buffer. 

Thus when:
```java
String s = sc.nextLine();
```
executes, it consumes the leftover newline character immediately instead of taking actual string input.

> **💡 Why Does This Happen?**
> Methods like `nextInt()`, `nextFloat()`, and `nextDouble()` consume only the numeric value. They do NOT consume the `ENTER` key. Thus, a buffer issue occurs.

### 🌟 Problem 2 — `nextChar()` Does Not Exist
The `Scanner` class has NO method named:
```java
nextChar()
```
Thus, a compiler error occurs 🚫.

### ✅ Correct Way to Take Character Input
Use:
```java
char ch = sc.next().charAt(0);
```
**Explanation:**
* `next()` → takes string token
* `charAt(0)` → extracts first character

### ✅ Corrected Program
```java
import java.util.*;

class ScannerDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        int a = sc.nextInt();
        sc.nextLine(); // Clears the buffer
        System.out.println("a = " + a);

        String s = sc.nextLine();
        System.out.println("s = " + s);

        char ch = sc.next().charAt(0);
        System.out.println("ch = " + ch);
    }
}
```

**🖥️ Sample Input**
```text
10
Java
A
```

**🖥️ Output**
```text
a = 10
s = Java
ch = A
```

### 🌟 Important Scanner Methods

| Method | Purpose |
| :--- | :--- |
| `nextInt()` | Integer input |
| `nextFloat()` | Float input |
| `nextLine()` | Entire line input |
| `next()` | Single word input |

### 🎯 Conclusion
This question demonstrates common Scanner-related issues involving buffer handling and character input. Proper understanding of input methods is essential for writing robust Java programs 🚀.

## 🧾 QUESTION 3(b)
**❓ Write a Java class having a method that opens a text file in read mode, selects all words containing at most one vowel, and writes them into another file.**  
**❓ Take source and destination file names from command line arguments.**

### ✅ Answer
This question combines:
* 📂 File handling
* 🧠 String processing
* 🚀 Command line arguments
* 💡 Character analysis

### 🌟 Problem Understanding
We must:
1. ✅ Read words from source file
2. ✅ Count vowels in each word
3. ✅ Select words having at most one vowel
4. ✅ Write them into destination file

### 🌟 What Are Vowels?
Vowels are: `a e i o u`. Both uppercase and lowercase must be considered.

### ✅ Complete Java Program
```java
import java.io.*;
import java.util.*;

class FileWordFilter {

    static int countVowels(String word) {
        int count = 0;
        word = word.toLowerCase();

        for(int i = 0; i < word.length(); i++) {
            char ch = word.charAt(i);
            if(ch == 'a' || ch == 'e' || ch == 'i' || ch == 'o' || ch == 'u') {
                count++;
            }
        }
        return count;
    }

    public static void main(String[] args) throws Exception {
        if(args.length < 2) {
            System.out.println("Provide source and destination files");
            return;
        }

        FileReader fr = new FileReader(args[0]);
        BufferedReader br = new BufferedReader(fr);

        FileWriter fw = new FileWriter(args[1]);
        PrintWriter pw = new PrintWriter(fw);

        String line;

        while((line = br.readLine()) != null) {
            String words[] = line.split("\\s+");

            for(String word : words) {
                if(countVowels(word) <= 1) {
                    pw.println(word);
                }
            }
        }

        br.close();
        pw.close();

        System.out.println("Filtered words written successfully");
    }
}
```

### 🌟 Example
Suppose the source file contains:
```text
sky
apple
try
book
gym
```
Words having at most one vowel:
```text
sky
try
gym
```

### 🌟 Important File Classes Used

| Class | Purpose |
| :--- | :--- |
| `FileReader` | Reads characters from file |
| `BufferedReader` | Efficient reading (reads lines) |
| `FileWriter` | Writes into file |
| `PrintWriter` | Convenient text writing |

### 🌟 Role of Command Line Arguments
* `args[0]` → source file
* `args[1]` → destination file

This program demonstrates efficient file processing, string manipulation, and command-line handling in Java 🚀.

## 🧾 QUESTION 3(c)
**❓ What is the drawback of creating a thread by extending Thread class?**  
**❓ How can this drawback be overcome?**  
**❓ Show how thread execution can be started.**

### ✅ Answer
Java provides two ways to create threads:
1. Extending `Thread` class
2. Implementing `Runnable` interface

### 🌟 Drawback of Extending Thread Class
Java does NOT support multiple inheritance. If a class extends `Thread`, then it cannot extend any other class ⚠️. Thus, flexibility decreases.

**❌ Example:**
```java
class MyThread extends Thread {
    // Cannot extend any other class now
}
```

### 🌟 Solution — Implement Runnable Interface
The `Runnable` interface solves this problem because the class remains free to extend another useful class.

**✅ Example Using Runnable:**
```java
class MyTask implements Runnable {
    public void run() {
        System.out.println("Thread Running");
    }
}

class Demo {
    public static void main(String[] args) {
        MyTask task = new MyTask();
        Thread t = new Thread(task);
        t.start();
    }
}
```
**Output:**
```text
Thread Running
```

### 🌟 How Thread Execution Starts
```java
t.start();
```
creates a new thread internally. Then the JVM automatically invokes:
```java
run()
```

### ⚠️ Important Difference

| Method | Meaning |
| :--- | :--- |
| `run()` | Normal method call (does NOT start a new thread) |
| `start()` | Creates a new thread and then calls `run()` |

### 🎯 Conclusion
Implementing `Runnable` is preferred over extending `Thread` because it supports better flexibility and object-oriented design 🚀.

## 🧾 QUESTION 3(d)
**❓ Discuss when synchronized block is better to use than synchronized method.**

### ✅ Answer
Synchronization is used to prevent:
⚠️ **Race Condition** when multiple threads access shared resources simultaneously.

Java provides:
1. `synchronized` method
2. `synchronized` block

### 🌟 Synchronized Method
The entire method becomes locked.
```java
synchronized void show() {
    // Critical and Non-critical code
}
```

### 🌟 Synchronized Block
Only specific critical sections become locked.
```java
synchronized(this) {
    // Only Critical code
}
```

### 🌟 When Synchronized Block is Better
A synchronized block is preferred when:
* ✅ Only a small portion of the code needs synchronization
* ✅ Better performance is required
* ✅ Entire method locking is unnecessary

> **💡 Why Better Performance?**
> A smaller locked region means less waiting time for other threads, better concurrency, and higher efficiency.

### ✅ Example
```java
class Counter {
    int count = 0;

    void increment() {
        System.out.println("Non-critical work"); // Executed concurrently

        synchronized(this) {
            count++; // Locked critical section
        }
    }
}
```

### 🌟 Benefit
Only `count++` is synchronized. The remaining code executes concurrently.
Problem with Synchronized Method: `synchronized void increment()` locks the WHOLE method unnecessarily.

### 🎯 Conclusion
Synchronized blocks provide finer control and better performance compared to synchronized methods because only critical sections are locked 🚀.

## 🧾 QUESTION 3(e)
**❓ State functionalities of:**
* `sleep()`
* `join()`
* `wait()`
* `notify()`

**❓ Provide overloaded versions if any.**

### ✅ Answer
These methods are extremely important for thread coordination and communication 🧵.

### 🌟 sleep()
**✅ Purpose**
Temporarily pauses the execution of the current thread.

**✅ Syntax**
```java
Thread.sleep(1000); // Pauses for 1000 milliseconds
```

**✅ Overloaded Versions**
```java
sleep(long millis)
sleep(long millis, int nanos)
```

**✅ Example**
```java
class Demo {
    public static void main(String[] args) throws Exception {
        System.out.println("Start");
        Thread.sleep(2000);
        System.out.println("End");
    }
}
```

### 🌟 join()
**✅ Purpose**
Makes one thread wait until another thread finishes execution.

**✅ Overloaded Versions**
```java
join()
join(long millis)
join(long millis, int nanos)
```

**✅ Example**
```java
class MyThread extends Thread {
    public void run() {
        for(int i = 1; i <= 5; i++) {
            System.out.println(i);
        }
    }
}

class Demo {
    public static void main(String[] args) throws Exception {
        MyThread t = new MyThread();
        t.start();
        t.join(); // Main thread waits until t finishes
        System.out.println("Main Ends");
    }
}
```

### 🌟 wait()
**✅ Purpose**
Makes the current thread wait until notified. Must be used inside a synchronized block/method.

**✅ Overloaded Versions**
```java
wait()
wait(long millis)
wait(long millis, int nanos)
```

### 🌟 notify()
**✅ Purpose**
Wakes one waiting thread.

**✅ Method Version**
```java
notify()
```

### 🌟 Difference Between `sleep()` and `wait()`

| Feature | `sleep()` | `wait()` |
| :--- | :--- | :--- |
| **Belongs To** | `Thread` class | `Object` class |
| **Lock Released?** | No | Yes |
| **Synchronization Required?**| No | Yes |

### 🎯 Conclusion
Thread coordination methods like `sleep()`, `join()`, `wait()`, and `notify()` are essential for efficient multithreaded programming and inter-thread communication 🚀.
